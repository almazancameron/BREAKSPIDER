# Breakspider Visual Direction — Prototype 02

## Purpose

The first implemented homepage prototype was structurally competent but aesthetically misinterpreted.

It translated Breakspider into the visual grammar of a polished editorial / creative-director portfolio: centered max-width composition, large symmetrical side margins, strong vertical reading column, clean section breaks, restrained stationery colors, physical-paper metaphors, tasteful serif emphasis, and poetic lifestyle-brand copy.

That is not the intended direction.

The earlier “sketchbook / forgotten notebook” language was meant to describe an emotional quality — personal, accumulated, exploratory, full of old ideas and strange objects — not a literal paper, desk, notebook, stationery, or scrapbook aesthetic.

Prototype 02 should be a new composition from first principles, not a reskin of Prototype 01.

## 1. Core thesis

Breakspider should feel like:

> **A personal internet profile from someone whose brain has been permanently altered by videogames, online communities, sprites, forums, weird UI, anime, memes, customization systems, and twenty years of internet use — but who also happens to be a very capable software engineer and game developer.**

The professional portfolio is important, but it should feel like it lives inside this person's internet space, rather than the site feeling like a professional portfolio decorated with internet references.

Useful shorthand:

> **What my profile would look like if the entire internet were one social network.**

And:

> **internet punk + videogame brainrot + customized profile + professional systems work**

The desired result is not retro cosplay. It should feel current, personal, and accumulated.

## 2. Emotional target

The site should feel:

- cozy
- chaotic
- funny
- specific
- slightly abrasive
- highly personal
- interactive
- game-literate
- internet-literate
- intentionally messy
- professionally credible underneath the mess
- worth poking at
- like there is always one more weird thing to click

Target roughly **6/10 chaos**.

The goal is:

> **chaos with a purpose, not purpose surrounded by chaos.**

Essential information must remain easy to find. Optional discoveries can be weird.

## 3. Cultural / aesthetic lineage

Breakspider's internet lineage is primarily **2007 onward**, not generic 1990s web nostalgia.

Relevant cultural memory includes:

- OG YouTube profiles
- Tumblr
- Gaia Online
- roleplay forums
- forum signatures
- avatars
- badges
- titles
- profile customization
- CSS-modified profile pages
- favorites modules
- embedded media
- little animated graphics
- fan-site visual clutter
- RPG inventories
- videogame menus
- character select screens
- collectible systems
- desktop widgets
- odd UI affordances
- game HUD fragments
- sprites and transparent PNGs
- sites where personal identity emerges through accumulated objects

Avoid generic “GeoCities / Y2K / vaporwave / CRT nostalgia” unless a specific asset genuinely calls for it.

This should not look like a theme pack called **RETRO INTERNET**.

## 4. Biggest correction: spatial composition

### Do not design Breakspider as a document.

The first prototype treated the homepage like a professional editorial document with unusual decoration.

Prototype 02 should treat the **desktop viewport itself as a customized profile canvas**.

At approximately 1440px wide:

- use much more of the horizontal viewport
- reduce conventional symmetrical page gutters
- allow content to approach the edges
- let some nonessential imagery partially leave the viewport
- use very different object scales
- create irregular clusters rather than centered sections
- allow objects to occupy genuinely different vertical positions
- break apparent columns
- let some graphics overlap other graphics
- let decorative objects intrude into otherwise empty regions
- preserve irregular pockets of breathing room

Negative space should feel like **open space between clusters**, not like the margins of a centered magazine layout.

Avoid this structure:

> hero → neat secondary row → divider → exploration section → footer

Professional material and personal / exploratory material should coexist in the same continuous spatial field.

Professional content receives **visual priority**, not a separate professional zone.

As the visitor moves outward or downward from the main focal area, stranger and more personal material can become more common.

## 5. Homepage hierarchy still matters

The existing wireframe hierarchy remains valid:

1. **Spotlight** — dominant
2. **About + Projects** — strongest secondary paths
3. Current Project / Sketchbook / Familiar / Changelog
4. Visitor profile / collectible state
5. Optional scraps, references, artifacts, weird clickable things

But this hierarchy should not be expressed as a conventional centered content column.

The Spotlight can dominate through size, contrast, media, motion, position, z-index, and proximity to high-value links.

About and Projects should remain obvious to a recruiter within seconds.

A recruiter should not need to understand the weirdness to find:
- who this person is
- what they do
- major work
- résumé/contact
- available-for-work state

A curious visitor should be able to ignore the recruiter path and immediately start clicking weird stuff.

## 6. Material language

Prototype 02 should feel **digital first**, not physical first.

Use freely:
- transparent PNGs
- sprites
- SVGs
- game screenshots
- UI crops
- vector graphics
- weird little emblems
- badges
- animated GIFs
- browser-native text
- CSS shapes
- deliberately crude icons
- pixel graphics
- cropped artifacts
- layered screenshots
- little UI labels
- status indicators
- profile modules
- menu-like elements
- desktop-like affordances
- old-profile-style modules
- game-menu framing
- floating icons
- cursor/follower elements
- slight compression / dithering / pixelization where appropriate

Use sparingly:
- literal paper
- tape
- corkboard / desk metaphors
- handwritten stationery
- physical notebook pages
- polaroid framing
- beige scrapbook surfaces
- faux printed-paper textures

A single physical-feeling object can exist if a specific asset benefits from it, but **paper should not be the global design system**.

## 7. Asset philosophy

The asset library is a **box of stuff**, not a checklist.

Do not try to use everything.

A small number of strong objects is preferable to covering the page in every available sprite.

Core identity-bearing material should primarily be creator-owned:
- Breakspider logo
- Breakspider splash animation
- Pixel Pugilists screenshots
- Viscap screenshots
- Familiar sprites
- original site UI
- original collectibles over time

Franchise-derived / reference material can appear as personal cultural texture:
- game icons
- badges
- Noise sprites
- avatars
- remixed references
- favorite-game objects

These should feel like **things inside the user's room**, not like the architecture of the room.

Do not use recognizable third-party material as the permanent core logo, primary navigation identity, or the only visual language holding the site together.

## 8. Visual vocabulary

Breakspider should feel assembled from multiple digital vocabularies.

### Clean native web
Use for:
- readable body copy
- links
- project facts
- contact information
- accessibility
- major CTA labels

### Game UI
Use for:
- counters
- profile state
- collectibles
- status labels
- Familiar details
- interaction feedback
- focus states
- tiny system readouts

### Profile customization
Use for:
- avatar
- badges
- equipped cosmetics
- little personal modules
- “currently doing” states
- favorite / random / rotating content

### Internet detritus
Use for:
- decorative scraps
- tiny GIFs
- badges
- strange transparent PNGs
- references
- random little artifacts
- visual jokes
- tiny unexpected clickable things

### Creator evidence
Use for:
- Viscap screenshots
- Pixel Pugilists screenshots
- code/editor captures
- process fragments
- diagrams
- rough UI states

These should mix together without being forced into one uniform illustration style.

## 9. Layout character

The page should have **character before decoration is added**.

If all custom assets are temporarily hidden, the underlying composition should still feel unusual.

Use:
- asymmetry
- large differences in scale
- broken columns
- edge proximity
- selective overlap
- floating modules
- offset clusters
- isolated micro-elements
- irregular density
- abrupt transitions in visual language where intentional

Do not rely on:
- rotating every box 2 degrees
- putting every label inside a blob
- making every image a crooked paper rectangle
- random positional jitter
- decorative offset with no reason
- identical “quirky” treatment repeated everywhere

Irregularity should belong to **objects and relationships**, not be sprayed onto every element.

## 10. Navigation

Navigation should remain simple and obvious:
- Home
- Projects
- About

Sketchbook may be contextual or secondary.

The nav can have playful vector backplates / sticker shapes, but the labels should remain unmistakable.

The entire sticker may tilt or shift as one object.

Do not randomly offset text independent of its background.

The nav should feel like customized profile UI, not luxury stationery.

## 11. Spotlight

The Spotlight is the strongest visual anchor.

Current job-search mode should clearly communicate:
- creator name
- software engineer / game developer identity
- short positioning statement
- available-for-work state
- About/contact
- Projects/work
- résumé

The Spotlight may use:
- a PP screenshot
- a Viscap crop
- an animated element
- a strange UI fragment
- a mixed-media composition

It does not need to resemble a paper note, portfolio hero card, or editorial feature box.

Its footprint should remain reusable for future modes:
- game release
- project demo
- site toy
- announcement
- interactive piece

## 12. Projects

The homepage project treatment should immediately show that there are at least two materially different kinds of work.

### Viscap
Should communicate:
> large interconnected professional software

Use real product screenshots and system relationships.

### Pixel Pugilists
Should communicate:
> game design + implementation + systems experimentation

Use gameplay, Priority Builder, combat, bracket, reward, Familiar, or Godot-process imagery.

Do not reduce these to two matching portfolio cards.

Their visual treatments may differ because the projects themselves differ.

## 13. Secondary homepage material

Secondary modules should not all become cards.

Possible forms:

### Current Project
- mini game-status module
- project badge
- small game menu
- sprite + status line

### Random Familiar
- free-standing sprite
- name
- tiny tags
- click target

### Changelog
- update.txt
- patch note fragment
- tiny console/module
- version readout

### Sketchbook
- microblog post preview
- forum snippet
- image + tiny excerpt
- recent-note feed item

### Visitor Profile
- profile/avatar widget
- game save/profile slot
- little customizable identity module

### Found Map / Artifact
- a literal vector object floating in the field
- not a paper note containing a drawing of an object

## 14. Interaction tone

Interactions should feel like things an internet- and game-literate person would enjoy discovering.

Good examples:
- hover promotes an overlapping object into focus
- click/tap opens an inspection state
- avatar opens visitor profile
- first collectible subtly changes the profile UI
- a sprite reacts to hover
- tiny object makes a sound
- cursor cosmetic unlock
- badge appears after discovery
- one strange UI element has physics
- screenshot pile can be shuffled / focused
- hidden object becomes inspectable

Do not turn navigation into a puzzle.

Important information should never require discovering a gimmick.

## 15. Copy voice

Prototype 01 used copy that sounded like a lifestyle brand / design manifesto.

Avoid that.

Do not write things like:
- “Made to be wandered through.”
- “Things left on the desk.”
- “A place to get lost in.”
- “Come explore my little corner.”
- “Built for curiosity.”
- “A collection of things that connect.”
- “There’s magic in the margins.”
- generic poetic statements about wandering, discovery, creativity, or making

The user likes discovery as a design principle, but does not naturally talk like a museum placard.

Desired copy voice:
- direct
- casual
- concise
- slightly funny
- internet-literate
- occasionally deadpan
- sometimes self-aware
- willing to be weird
- never inspirational-poster language
- never precious

When real copy has not been supplied:

> **Use neutral functional placeholder copy rather than inventing personality-heavy prose.**

Prefer:
> Working on Pixel Pugilists right now.

over:
> A strange little world currently taking shape.

Prefer:
> Site changelog

over:
> Notes from the margins.

Prefer:
> More stuff

over:
> Keep wandering.

Do not try to imitate the user's personality through excessive slang. Restraint is better than fake voice.

## 16. Typography

Avoid making the whole site feel scholarly, literary, or editorial.

Do not make a high-contrast serif italic the primary source of personality.

A serif can appear somewhere if it creates an intentional clash, but the overall system should feel more like:
- web
- UI
- videogame
- profile
- forum
- utility
- punk graphic design

than:
- literary journal
- design magazine
- art-school portfolio
- notebook
- boutique agency

Typography can mix families if roles are clear.

Possible roles:
- bold display sans / grotesk for major anchors
- mono or bitmap-flavored type for metadata / UI
- readable sans for body copy
- occasional eccentric display face for one-off objects

Do not make every piece of text stylized.

## 17. Color

Prototype 01 leaned heavily toward tasteful cream / charcoal / muted stationery colors.

Prototype 02 can be more digitally saturated and game-like.

No fixed palette is mandated yet, but consider:
- deep near-black / dark UI areas
- warm off-white where useful
- acidic or candy accent colors
- bright status colors
- game-UI cyan / orange / red / lime used selectively
- colors sampled from actual PP / Viscap / asset material
- unexpected clashes in small doses

Avoid turning it into generic cyberpunk neon.

Color should feel **collected and intentional**, not like a predefined startup palette.

## 18. Desktop vs mobile

Desktop is the canonical expressive composition.

Mobile should not attempt to preserve absolute desktop coordinates.

On mobile:
- preserve content priority
- keep Spotlight first
- keep About / Projects easy to reach
- convert hover to tap
- reduce overlap
- simplify decorative density
- allow a more linear feed when needed
- keep enough strange detail that it still feels like Breakspider

Do not simply shrink the desktop canvas.

## 19. Prototype 02 engineering scope

Build a fresh homepage prototype.

Preserve Prototype 01 for comparison.

Recommended:
- create a new route, branch, or alternate implementation
- do not incrementally mutate Prototype 01 until it becomes unrecognizable
- reuse functional components where helpful
- reconsider layout composition from scratch

Implement:
- splash → homepage transition
- header
- navigation
- audio control
- visitor avatar/profile
- Spotlight
- About
- Projects
- current PP
- Sketchbook
- Familiar
- changelog
- one found object / Map
- artifact focus interaction
- basic mobile translation

Deeper routes may remain stubs during this visual pass.

Use actual assets.

Avoid placeholders when a real candidate exists.

## 20. Concrete rejection criteria

Prototype 02 is still wrong if:

- it looks like a tasteful creative-agency portfolio
- it looks like a centered editorial webpage
- it looks like a literal notebook or scrapbook
- it has huge symmetrical side gutters
- it is organized primarily as stacked horizontal sections
- the weirdness appears only as decoration around conventional cards
- all content has matching containers
- every irregular element uses the same polygon/blob treatment
- the page could be recreated by starting from a normal portfolio template and swapping in quirky graphics
- the copy sounds like a lifestyle brand
- the references to games/internet culture feel like tasteful easter eggs rather than part of the site's native language
- the page feels more “designer” than “person on the internet”

## 21. Success criteria

Prototype 02 is moving in the right direction if:

- the 1440px viewport feels actively composed edge-to-edge
- the Spotlight is immediately dominant
- About and Projects are still obvious within seconds
- screenshots, sprites, vector shapes, text, and UI fragments coexist naturally
- some areas are dense and others unexpectedly empty
- the page feels customized rather than templated
- a visitor can tell the creator likes videogames before reading an About paragraph
- the page feels current despite drawing from older internet culture
- the page contains at least one interaction that feels delightful rather than merely decorative
- the layout itself has personality before polish
- it feels plausible that the site could keep accumulating strange objects for years
- the professional work feels stronger because it is presented inside a distinctive personal context

## 22. Final mental model

Do not think:

> “How would a creative agency design a portfolio for this person?”

Think:

> **What if this person's profile page became an entire website?**

Do not think:

> “digital sketchbook.”

Think:

> **customized internet space full of game UI, profile modules, project evidence, sprites, screenshots, badges, weird files, and things accumulated over time.**

Do not think:

> “professional site with chaotic decoration.”

Think:

> **chaotic personal internet space with a very clear professional spine.**

That distinction is the foundation of Prototype 02.
