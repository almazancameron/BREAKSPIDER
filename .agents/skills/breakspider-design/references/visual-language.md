# Breakspider visual language

## Core idea

Breakspider is a customized personal internet profile belonging to a software developer and game developer, not a studio landing page or a conventional portfolio with novelty graphics. The emotional target is **cozy + chaotic + playful + professional underneath the mess**. Aim for roughly 6/10 maximalism: busy enough to feel accumulated and personal, controlled enough that hierarchy is immediate.

Two visitors must succeed at once:

- A 30-second visitor quickly finds identity, engineering strengths, current work, projects, contact, and availability.
- A 20-minute visitor discovers Familiars, process material, collectibles, jokes, interactions, and personal references.

Professional information gets visual priority, not a visually separate corporate zone. Optional strangeness grows outward and downward from the main anchors.

## Composition grammar

- Compose desktop as an authored field, not a centered document: use the width, approach edges, break columns, vary scale, and create irregular clusters.
- Build a dominant anchor first. On Home this is the interchangeable Spotlight; About and Projects follow clearly, then current activity, Sketchbook, Familiars, changelog, and discoveries.
- Let density vary. Busy edges and archive pockets can sit beside quiet dark regions. Negative space is room between clusters, not symmetric magazine gutters.
- Give the layout character before decoration. If sprites and scraps disappear, asymmetry, hierarchy, typography, and object relationships should still feel like Breakspider.
- Use overlap to express relationships: a project capture crossing its work surface, a portrait bridging identity and biography, or archive material tucked behind an inspectable file. Keep important text and controls unobstructed.
- Use the homepage as a family reference, not a page template. Interior routes follow “same person, same internet space, different room”: profile, work archive, game workbench, connected software system, microblog, bestiary, collection, or route graph.

## Material and provenance

Mix digital materials with visibly different origins:

- ordinary web text and links for clarity;
- bold sans display type for major destinations;
- mono/bitmap-flavored labels for status, files, versions, counters, and interface readouts;
- real project screenshots, game captures, sprites, vectors, badges, GIFs, and custom interface fragments;
- occasional internet detritus as personal texture.

Digital-first does not mean generic cyberpunk. The stable ground is deep navy/near-black with warm cream text and selective lime, cyan, pink, and orange accents. Project work keeps its native palette—ONFF orange/cyan, Viscap blue/dark UI, Familiar colors—rather than being recolored into one brand scheme.

Physical scrapbook devices such as paper, tape, corkboard, polaroids, and beige stationery are occasional object treatments, not the global design system.

## Frames, components, and reuse

A frame should explain an object: Spotlight is a work surface, Projects stages evidence, Changelog is an update file, and inspectable artifacts behave like files. About, current work, a Familiar, or a Sketchbook fragment may be stronger without a box.

Extract repeated state, persistence, audio, dialog lifecycle, media inspection, content records, and real domain concepts. Keep bespoke page composition and page-owned responsive CSS local. Do not create universal cards, section wrappers, coordinate schemas, page renderers, or diagram engines merely because pages share tokens.

## Interaction and voice

Interactions should reveal, reward, communicate, or perform a job. Hover may enhance focus but cannot gate content; provide tap and keyboard equivalents. Motion is short and tactile, with reduced-motion support. Functional objects are semantic controls with visible focus; quiet decoration is hidden from assistive technology.

Copy is direct, concise, casual, internet-literate, and occasionally deadpan. Prefer `Working on ONFF` or `Site changelog` to invented poetic language about wandering, magic, margins, or creativity. Use neutral functional placeholders when real copy is missing.

## Rejection checks

Reject or revise a direction when it becomes:

- a sparse hero followed by neat reusable sections;
- a conventional three-card developer portfolio;
- a centered editorial or tasteful creative-agency layout;
- a literal notebook/scrapbook or generic retro/Y2K theme;
- a uniform grid where every item has the same container;
- weirdness applied only as stickers around conventional cards;
- generic neon cyberpunk;
- a theme-park game HUD that harms normal reading;
- difficult navigation justified as discovery;
- personality-heavy prose invented to fill content gaps.

## Example: “clean up the homepage”

Keep the Spotlight dominant and recruiter paths explicit, then improve collisions, typography, and cluster rhythm. Re-curate decorative objects from the full asset library, leaving some edges active and some dark space open. Do **not** replace the field with one hero, a row of destination cards, and a single decorative image; that solves clutter by deleting Breakspider's identity.

## Review questions

1. Can a professional visitor understand the creator and reach Projects/About/contact immediately?
2. Does the layout itself feel customized before decorative assets are counted?
3. Do clusters, open areas, and overlaps look authored rather than evenly distributed?
4. Does each asset have a relationship to identity, content, interaction, or nearby structure?
5. Does the page keep its own room-specific composition instead of inheriting a generic template?
6. Would the result still feel like Breakspider if the nostalgia cues were removed?
